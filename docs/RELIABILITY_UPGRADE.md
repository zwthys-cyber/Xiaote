# 3.2.0 可靠性与体验升级

本轮聚焦车辆状态、命令串行执行和账号恢复，不改变被动钥匙的协议实现。

## 行为变化

- 只有实际返回的状态类别才更新读取时间。主页显示部分刷新失败；组合状态的时间取所需类别中最早的一次，不再用媒体读取掩盖旧门锁状态。
- 锁车、解锁后回读真实门锁状态，未取得回读时提示“指令已发送，车辆状态尚未确认”。
- 用户命令在 Face ID 验证前占用操作位置，等待当前读取完成；后续轮询读取让出通道。等待最多 30 秒，不自动重发车辆命令。
- 切车、断连和后台暂停会使旧操作失效。场景授权绑定任务批次，不能供其他入口借用；失败后停止后续步骤。
- 通知只使用本轮实际取得的电量、门窗和充电状态。部分关闭字段不能证明全部已关闭，正常停止充电不再触发异常提醒。
- 账号区分连接中、可用、暂不可用与授权失效，提供重试或重新登录。临时网络错误保留缓存；退出后旧请求不能回填账号数据。
- 后端按会话合并令牌刷新。退出不再依赖 Tesla 刷新成功，退出期间返回的刷新结果不能重新写入已删除会话。暂时不可用返回 503，明确失效返回 401。

## 设备验收

1. 媒体轮询和下拉刷新期间点击锁车：立即出现等待/执行反馈，车辆命令只发送一次。
2. Face ID 等待期间重复操作或切车：只有原有效任务可执行，旧认证结果不能控制新车辆。
3. 断开车辆响应后刷新：不显示新的成功更新时间，不根据旧状态生成提醒。
4. 锁车指令确认但回读无响应：保留旧显示并明确提示尚未确认。
5. 手动停止充电、预约等待：不因“停止”文字发送异常通知；供电缺失只作供电提醒。
6. 账号授权失效：出现重新登录入口；断网则保留缓存并显示重试连接。
7. 账号加载中退出后重新登录：旧响应不覆盖新账号。
8. 回归正常配对、后台无感进入、场景失败中止和多车切换。

模拟器和单元测试无法替代真车 BLE、Face ID、后台调度和耗电验证。

## 第二轮：操作反馈与日常体验

- 手表请求包含命令编号、车辆标识与有效期。iPhone 在执行前原子保存记录，重复请求只返回原结果；iPhone/Watch 重启后会把未完成请求标为尚未确认，不自动重发。
- 手表分别呈现手机可达性、车辆数据时间和命令结果。锁车/解锁使用明确按钮，避免根据旧门锁状态反向操作。成功回执要求实际回读；闪灯/鸣笛显示车辆接受指令。
- 场景可以拖动排序并查看逐步反馈。失败后保留已完成步骤，停止后续步骤；切车或断连时，不把正在执行的步骤误标为未发送。编辑有改动时取消需确认。
- 首页分别显示无感钥匙、本地控制、云端状态；电量、续航和门锁使用字段级读取时间。超过两分钟标为旧数据，刷新其他字段不能使它们变新。
- Siri 操作使用稳定的命令返回值与真实回读，不再依赖 700ms 的成功动画；失败时同样释放临时连接。

新增设备验收：
1. Watch 点击锁车，依次出现发送/执行/确认，拔开连接则出现尚未确认，不自动重发。
2. 操作期间切车，旧请求不能控制新车；较晚到达的回执不能覆盖更新的操作结果。
3. 重启 Watch/iPhone 后刷新连接，能恢复已知结果，未确认请求不会重新执行。
4. 场景拖动排序保存后按新顺序执行；中途失败只保留之前步骤的结果。
5. 编辑场景后取消，确认放弃才能退出；大字体下步骤说明和连接状态可完整阅读。
6. 静置超过两分钟，首页和 Watch 主动标出旧数据，不依赖下一次车辆响应。
