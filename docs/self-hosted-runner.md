# 可选：使用自己的 Mac 构建

当前主线使用 GitHub 托管的 `macos-26` Runner，不依赖 `xiaote-mac`。本文仅供维护者有意改用自托管 Mac 时参考，不描述当前默认部署。

## 准备与注册

在独立编译用户下安装与工作流匹配的 Xcode 26.2、iOS/watchOS SDK 和模拟器运行时。不要在该用户下保存日常 Apple ID、签名证书或个人 SSH 私钥。

通过仓库 **Settings → Actions → Runners → New self-hosted runner** 获取当时有效的下载、校验与注册命令。可选择名称和自定义标签 `xiaote-mac`，不要把短期注册令牌提交到仓库。按 Runner 安装目录提供的 `svc.sh` 安装和启动服务，确认在线且标签匹配。

## 修改工作流时的要求

- 明确将需要自托管的 Job 的 `runs-on` 改为相应标签，并同步校正 `DEVELOPER_DIR`。
- 保留模拟器回归测试、协议验证和无签名真机构建步骤。
- 限制自托管 Job 只执行可信仓库代码，不直接运行外部 PR。后端与协议测试可继续使用 GitHub 托管 Runner。
- 当前流程没有配置跨运行持久缓存；不能仅注册 Runner 就假设依赖或 DerivedData 已缓存。若另行配置缓存，必须与 Xcode、依赖版本及并发任务隔离。
- 不在不同任务之间共享 IPA staging 或测试结果目录，避免产物混用。

## 运维检查

Mac 需开机联网、预留编译空间；模拟器测试还需可用的图形会话和对应运行时。检查 Runner 服务、Xcode 许可与首次启动组件，以及 iOS/watchOS SDK。删除缓存前先确认实际路径与是否有任务正在使用，不直接复制旧脚本中的目录删除命令。

产物名称、保留时间、安装与发布流程统一见 [构建、安装与发布](BUILD.md)。
